# FR-401: Normalize text on the Kani proof path without allocation or iterator loops

## Description

When the Kani text carrier (ticket IR-1445) needs the retained sequence of a payload under `nfc`, `nfd`, `nfkc` or `nfkd`, the kernel SHALL provide a normalization over fixed-capacity buffers whose scalars, order and count equal those of the shipped `NormalizationForm::apply`. The shipped `apply` streams through `unicode-normalization` iterators and `prepare` collects into `String`s, which the IR-1436 design review (D4) bans from a Kani carrier. Contract Codegen (CG FR-052, prerequisite P4, ticket IR-1501) gates every normalizing-profile criterion on this requirement, and without it those profiles are `unsupported`.

**Reading of "loop-free".** The code lead ruled (ticket IR-1501) that "loop-free" means no iterator adapter, no `chars()`, no allocation, no recursion and no data-dependent loop bound. Indexed loops with a constant bound are permitted, because Kani unwinds them to a stated finite bound. This is an interpretation of the wording of IR-1501 and CG FR-052, not a narrowing of it.

**Relation to IR-1445.** The function is generic over its capacities (below), so its host criteria stand without the carrier. Instantiating the capacities with the carrier's C, and the Kani run and its memory evidence, belong to IR-1445 and are conditional on it; a table that does not fit the K-DR budget is IR-1445's measurement and leaves the normalizing profiles `unsupported` in CG FR-052, with this requirement still met on the host.

## Inputs

- A normalization form (`nfc`, `nfd`, `nfkc`, `nfkd`).
- A payload `&[u8; N]` and a length `len`, where N is a const generic (the carrier instantiates it with C).
- An output buffer `&mut [u8; R]` and an intermediate decomposition buffer of D scalars, where R and D are const generics. For an operand with declared `max`, the instantiation has R at least `4 * max` and D at least `payload_scalar_ratio * max` ([FR-400](./FR-400-text-payload-byte-bound-per-profile.md)), each an upper bound on what an admitted retained sequence needs.

## Outputs

The retained scalars in the output buffer as UTF-8, their scalar count and byte length, or one refusal of `NormalizeRefusal`: `ExceedsCapacity`, `InvalidUtf8` or `LengthAboveCapacity`. The function is callable from a host build.

## Behavior

1. **Constant tables owned by quire-exact.** The function reads constant tables of this crate: the full canonical and compatibility decomposition of every scalar that has one, the canonical combining class, and the primary composition triples (left, right, composite). It reads no `unicode-normalization` item at run time. Hangul syllables are decomposed and composed by the algorithm with constant arithmetic. Table lookup is indexed access, with constant-bound search loops.
2. **How the tables are generated and pinned.** The tables are generated const data, checked in, produced by a generator that enumerates every Unicode scalar through the public API of the `unicode-normalization` dependency (`char::decompose_canonical`, `decompose_compatible`, `canonical_combining_class`, and `compose` over the scalars of each canonical decomposition taken left to right) and writes the const source. Generation is a separately invoked mode (an explicit command, for example an environment variable or a feature that the default `cargo test` does not set); the default test run never writes `src/` and only compares the checked-in table with a regenerated one in memory. The file carries no hash, digest or version literal. What guarantees the table is the exhaustive host test of FR-401-AC-8 against that public API and against `NormalizationForm::apply`, not review of the file. Composition exclusions, singleton and non-starter decompositions, canonical reordering by combining class and the blocked-composition rule follow from that data and from `apply`'s behaviour as checked.
3. **Same result.** For every payload within N, form and capacities, the emitted scalars and count equal those of `NormalizationForm::apply` when the output fits. The count is the running emitted count of `text.normalize-output`, so the carrier's `compare_text` replacement charges the same points as the shipped `compare_text`.
4. **Capacity failure mode.** Decomposition runs in place in the D-scalar buffer, reordering runs over that buffer, and composition writes into the R-byte output. When the intermediate form exceeds D scalars or the output exceeds R bytes, the function returns `ExceedsCapacity` and no partial result is used. With D and R as in Inputs, an exceeded D or R means the retained sequence has more than `max` scalars (for `nfd` and `nfkd` the intermediate is the retained sequence; for `nfc` and `nfkc` it is at most `payload_scalar_ratio` times the retained length, FR-400), so the refusal is a correct negative for the draw constraint of CG FR-052. `len` above N returns `LengthAboveCapacity`, and bytes that are not UTF-8 return `InvalidUtf8`.
5. **No hidden cost.** The function charges no `Meter` (metering is the replacement `compare_text`'s) and allocates nothing.
6. **Checkable module.** The proof-path normalization sits in its own module. Every loop in it is `for <index> in 0..<NAME>` with `NAME` a named constant of the module or one of the const generics N, D or R. The module exposes `unwind_bound` as a `const fn unwind_bound<const N: usize, const D: usize, const R: usize>() -> usize`, the largest declared loop bound of that instantiation plus one, which is the unwind bound a Kani harness needs at the carrier's instantiation.

## Status

Planned (IR-1501). No Rust or test exists. The reading of "loop-free" above is the code lead's ruling on IR-1501, recorded here as an interpretation of the IR-1501 and CG FR-052 wording, not a narrowing.

Open premise, not claimed: that Kani verifies the table lookups and the composition within the carrier's memory budget is not established here; the memory evidence is IR-1445's.
